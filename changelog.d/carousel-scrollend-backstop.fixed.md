- **A looping carousel that gets no `scrollend` still comes home.** Chrome can send a scroll event and no `scrollend` (for example, when the page shortens and the browser pulls the scroll back). A looping row (`loop: true`, plain or spotlight) that glided across the seam then rested on a clone: it did not jump to the real slide and did not fire `studio:carousel:change`. `studio/carousel` now has `watchRest`: `scrollend` rests the row, and 450 ms after the last scroll event (`REST_CAP_MS`, three of the 150 ms quiet spells, `SETTLE_MS`) is the backstop. After the controller's own scroll, a `scrollend` counts only once a scroll event has come since that scroll, so the end of a replaced glide does not cut the new one short. The change event still fires once per move. A cascade row does not scroll, so this does not change it. Nothing for a consumer to do.
