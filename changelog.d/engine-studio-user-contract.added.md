- **`Studio::Account`, the engine-owned account contract.** `include Studio::Account` in `User` gives `admin?`, a default `display_name`, `normalizes :email` (blank stored as NULL), `validates :role, inclusion:` against the new `Studio::Roles` (`viewer`, `member`, `admin`; a host may narrow it with `studio_roles`, never widen it), `Sluggable` and `Studio::OmniauthUser`. `Studio::Account.find_by_email` is the one safe lookup by address (blank finds nobody, `LOWER(email)`), and `Studio::Account.race_winner` is the race rescue for a host's own `from_omniauth` (verified address only; logs to `ErrorLog.capture!` when nothing matches). The new host migration `AddUsersRoleKnownCheck` installs CHECK `users_role_known` and NOT NULL, skips an app that already has the CHECK, and refuses on a stray role. Nothing changes until an app includes the concern or installs the migration. See docs/USER_CONTRACT.md, "The account concern". (The audit called it `Studio::User`; that name would shadow the host's `User` inside `module Studio`.)
