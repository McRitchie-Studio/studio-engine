- **The engine tables refuse a NULL slug, and users refuse a NULL role.** A new migration, `AddEngineNotNullChecks` (run `bin/rails studio_engine:install:migrations`), backfills any NULL slug on `error_logs`, `theme_settings`, `studio_geo_settings` and `studio_site_identities` by its model's rule and any NULL `users.role` with `viewer`, then adds a validated CHECK `<column> IS NOT NULL` named `<table>_<column>_present`. It is the NOT NULL step that 0.141.0 deferred. It is a CHECK, not a column-level NOT NULL, so `db/schema.rb` only gains lines and the release's schema-dump guard accepts it; the dump after a migrate equals the dump after a schema load. A role column that is already NOT NULL (the hub, Turf) gets no CHECK. Adopt it only on a host whose production has run 0.141.0 or later for one release: up to 0.137.0, `ErrorLog.capture!` inserts a NULL slug first. To roll a host back to a release older than 0.141.0, run `bin/rails db:migrate:down VERSION=<this migration's installed version>` first; a rollback to 0.141.0 or later needs nothing.
