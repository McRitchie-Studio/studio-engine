- **`Studio::ButtonComponent`, `Studio::EmptyStateComponent` and `Studio::TableComponent`.** The engine's first UI primitives after the badge, so apps stop hand-building buttons, empty states and tables (UI/UX audit 2026-11-07, §4D). The button maps four tones (`primary`, `secondary`, `quiet`, `danger`) and three sizes onto the shipped `btn-*` utilities, renders a `<button>` or an `<a>`, and its `loading:` state is the aria-busy contract with the pending spinner. The empty state is the `.empty-state` card with an icon, a message, a detail line and one Button action. The table takes columns and rows, sorts through plain `?sort=&direction=` links with `aria-sort`, renders an empty row, and scrolls sideways on a phone. `/admin/style` draws every tone, size and state live, and `e2e/ui_primitives_screenshots.spec.js` compares each specimen to a Linux baseline at 390 and 1280 px in light and dark. Consumers adopt them in later releases; nothing changes until a view renders one.
